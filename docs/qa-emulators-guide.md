# Гайд QA-эмуляторов для тестирования fcpolotsk.by

Что установить, как открыть сайт на разных «устройствах», что искать.
Цель — за час обойти основные платформы и найти визуальные баги.

---

## Уровень 0. Chrome DevTools (бесплатно, везде)

Самый быстрый способ, не требует ничего кроме браузера. Эмулирует
размеры экранов, но **не настоящие движки** — Safari iOS и Android Chrome
будут отрисованы движком твоего десктопного Chrome'а (Blink). Хватает
для 80% багов вёрстки.

### Как открыть

1. Открой `https://fcpolotsk.by` в Chrome (или Edge — то же самое).
2. Нажми **F12** или **Ctrl+Shift+I** → вкладка Elements.
3. Сверху слева в DevTools нажми иконку телефона/планшета (или **Ctrl+Shift+M**).
4. В верхней панели появится Device toolbar.

### Что выбрать в Device

В dropdown'е сверху по центру выбирай:
- **iPhone SE** — самый узкий iOS (375px)
- **iPhone 14 Pro Max** — большой iPhone (430px)
- **iPad Mini** — узкий планшет (768px)
- **Samsung Galaxy S20 Ultra** — Android (412px)
- **Responsive** — задать любой размер вручную

Между ориентациями переключай иконкой «↺ Rotate» справа от dropdown'а.

### Что проверить в Chrome DevTools

После выбора устройства обойди все главные секции главной страницы
(скроллом). Потом перейди на:
- `/news` (список новостей)
- `/news/[любая]` (страница новости)
- `/match-admin/login` (логин в админку — туда не входи без пароля)

Чеклист на каждом экране в файле `docs/ui-test-prompt.md` (раздел
«Чеклист проверок»).

### Минусы DevTools

- Не настоящий Safari → не ловит iOS-специфичные баги (sticky, momentum scroll, safe area, viewport units)
- Touch events эмулируются, но иногда работают иначе чем на реальном устройстве

## Уровень 1. Свой смартфон (бесплатно, идеально)

Если у тебя есть iPhone или Android — это лучший тест. Реальный движок,
реальные жесты, реальные шрифты.

1. Открой `https://fcpolotsk.by` в нативном Safari (iOS) или Chrome (Android).
2. Скролль, тапай по всему, читай тексты.
3. Особенно проверь:
   - Не залипает ли header при скролле
   - Не дрожит ли live-минута в LIVE-карточке
   - Нет ли горизонтального свайпа (страница не должна елозить вбок)
   - Тапы по кнопкам срабатывают с первого касания

## Уровень 2. iOS Simulator (бесплатно, только Mac)

Реальный движок Safari iOS — ловит баги которых нет в Chrome DevTools.
Доступно только на macOS.

### Установка

1. App Store → найди **Xcode** → Install (~10 ГБ, может тянуть час)
2. После установки запусти Xcode хотя бы раз — он попросит установить
   Command Line Tools, согласись.
3. Открой Xcode → меню **Xcode** → **Open Developer Tool** → **Simulator**.
4. В Simulator: меню **File** → **Open Simulator** → выбери модель
   (iPhone 16, iPhone SE, iPad Pro …).

### Использование

1. В симуляторе откроется виртуальный iPhone.
2. Открой Safari (через Home screen).
3. Введи `https://fcpolotsk.by`.
4. Жесты:
   - Скролл — drag мышью
   - Pinch zoom — Alt + drag
   - Home — Cmd+Shift+H
   - Rotate — Cmd+→ / Cmd+←
5. DevTools через десктопный Safari: открой Safari на Mac → меню
   **Develop** → имя симулятора → выбери страницу.

### Минимальный набор моделей

- iPhone SE (3rd gen) — узкий, старый-стиль
- iPhone 16 — современный, с Dynamic Island
- iPhone 16 Pro Max — большой
- iPad Mini — узкий планшет
- iPad Pro 12.9" — большой планшет

## Уровень 3. Android Emulator (бесплатно, кроссплатформенно)

Реальный Android — нужен для проверки Chrome Android и WebView. Тяжелее
чем iOS Simulator (требует виртуализацию).

### Установка

1. Скачай **Android Studio**: https://developer.android.com/studio (~3 ГБ)
2. Установи (Windows / Mac / Linux). При первом запуске мастер скачает
   SDK + Emulator (~5 ГБ).
3. Открой Android Studio → меню **Tools** → **Device Manager** (или
   иконка в правой колонке).
4. **+ Create Virtual Device** → выбери модель → выбери System Image
   (Android 14 или 15, x86_64 рекомендуется).
5. Скачается образ (~1.5 ГБ на модель).
6. Жми «Play» → запустится виртуальный телефон.

### Использование

1. В эмуляторе откроется Android-телефон.
2. Свайпни вверх → найди Chrome → открой `https://fcpolotsk.by`.
3. DevTools: подключи USB-кабель… нет, шучу. Открой `chrome://inspect` в
   десктопном Chrome → раздел **Remote Target** покажет эмулятор → жми
   inspect на странице.

### Минимальный набор моделей

- **Pixel 6a** — типичный Android-телефон (412×915)
- **Pixel Fold** — экзотика, узкий складной экран
- **Pixel Tablet** — Android-планшет

### Минусы

- Очень тяжёлый, требует 8+ ГБ RAM
- Запускается ~30 сек
- На macOS требует Apple Silicon для приличной скорости

## Уровень 4. Онлайн-сервисы (платно/триал, real devices)

Если нужно проверить редкое устройство (Galaxy Fold, старый iPhone 8,
конкретный Android Browser) — берёшь реальный девайс в облаке.

### BrowserStack

- https://www.browserstack.com → free trial (30 минут)
- Real devices — iPhone, Samsung, Pixel, Huawei всех поколений
- Запускаешь в браузере, видишь экран реального устройства, тапаешь
  мышью / touchpad-ом
- Удобно для одноразовой проверки на старых iOS / редких Android

### LambdaTest

- https://www.lambdatest.com → free trial
- Аналогично BrowserStack, иногда дешевле

### Responsively App

- https://responsively.app → бесплатно, локально
- Запускает 4-9 viewport'ов одновременно в одном окне, скролл
  синхронизирован
- Идеально для быстрого обхода брейкпоинтов

## Чеклист проверок (краткий)

На каждом устройстве пройди:

### Главная (`/`)

- [ ] Hero «БЕЛО/ЭРА» — текст не наезжает на бейдж сезона
- [ ] Карточка следующего матча — счёт читаем, таймер тикает, дата/время помещаются
- [ ] Пост-матч карточка после игры — бомбардиры читаемы, не сливаются
- [ ] Все 7 секций без горизонтального скролла
- [ ] Footer — лого, ссылки, копирайт на месте

### Матчи (`#matches`)

- [ ] «Игры сезона» заголовок не обрезан
- [ ] Карточка «Следующий матч» — все 3 иконки (дата/время/стадион) в один или три ряда, читаемы
- [ ] Кнопки «Статистика» / «В календарь» — есть focus-ring при тапе
- [ ] Таблица «Последние матчи» — счета не наезжают на названия
- [ ] Standings table — позиция, лого, имя, M, очки — все колонки помещаются

### Команда (`#team`)

- [ ] Pill-фильтры (Все/Вратари/…) переносятся на новую строку если не помещаются
- [ ] Карточки игроков — фото 3:4 не растянуто, имя и позиция читаемы

### Новости (`#news`)

- [ ] Карточки кликабельны (тап → переход на `/news/[slug]`)
- [ ] Excerpt не выходит за карточку

### Страница новости (`/news/[slug]`)

- [ ] Заголовок не вылетает за viewport
- [ ] Лид-текст имеет левую полосу-акцент
- [ ] ShareBar — кнопки 40×40, не слипаются
- [ ] Sidebar справа на десктопе, под статьёй на мобиле
- [ ] Related news внизу — 3 карточки на десктопе, 1 на мобиле

### Match Admin login (`/match-admin/login`)

- [ ] Тёмный фон, форма по центру
- [ ] Input для пароля принимает текст
- [ ] При неверном пароле — красный блок ошибки

## Какие баги отдавать обратно

Когда что-то сломалось — нужно три вещи:

1. **Скриншот** проблемы (Win+Shift+S / Cmd+Shift+4)
2. **URL** + **устройство** + **разрешение**
3. **Описание словами** — что должно быть, что есть, в чем расхождение

Пример хорошего отчёта:
> **Pixel 8 Chrome (412×915), https://fcpolotsk.by главная**
> В hero текст «БЕЛОСИНИЙ» лезет на бейдж «Сезон 2026» сверху, между
> ними не остаётся отступа. На iPhone 16 — то же самое.
> Скриншот: bug-1.png

Пример плохого:
> «Что-то не так с заголовком, посмотри»

## Как часто тестировать

| Когда | Что проверять | Кому |
|---|---|---|
| После каждого пуша в main | Chrome DevTools 3 viewport'а + свой телефон | Алекс |
| Перед матч-днём | Полный обход 5-устройственного minimum'а + админка с тренировочным паролем | Алекс или брат |
| Раз в месяц | Полный обход всех уровней (DevTools + Sim + Real + BrowserStack) | Брат |
