# Импорт матчей из CSV — инструкция

Для матчей, которых нет на bel.football (региональный этап Второй лиги, товарищеские, ветеранские). Заполняешь две таблицы — скрипт заливает всё в Sanity одной транзакцией. Вбивать руками в Studio не нужно.

**Схему менять не требуется.** Скрипт пишет в существующие поля `match`.

## Файлы

```
apps/studio/
├── data/
│   ├── matches.csv          # один матч = одна строка
│   └── events.csv           # одно событие = одна строка
└── scripts/
    └── import-matches.ts
```

## Быстрый старт

```bash
# 1. Заполнить apps/studio/data/matches.csv и events.csv

# 2. Сухой прогон — покажет что будет сделано, ничего не запишет
pnpm --filter @fc-polotsk/studio import:matches

# 3. Запись
pnpm --filter @fc-polotsk/studio import:matches -- --apply
```

Нужен `apps/studio/.env.local` с `SANITY_STUDIO_PROJECT_ID`, `SANITY_STUDIO_DATASET`, `SANITY_STUDIO_WRITE_TOKEN` — тот же, что для `seed`.

## matches.csv

| Колонка | Обязательна | Что писать |
|---|---|---|
| `key` | да | Стабильный идентификатор матча: `region-01`, `region-02`… Из него строится `_id` документа. **Не менять после импорта** — иначе создастся дубль |
| `date` | да | `2026-04-19` |
| `time` | нет | `17:00`. Пусто → 00:00. Время минское (UTC+3) |
| `competition` | да | `Вторая лига. Региональный этап` — строка показывается на сайте как есть |
| `tour` | нет | Номер тура, целое число |
| `home` | да | Название команды хозяев **как в Sanity** |
| `away` | да | Название команды гостей |
| `venue` | нет | Стадион. Если внутри есть запятая — взять в кавычки |
| `status` | нет | `finished` (по умолчанию) · `scheduled` · `live` |
| `hs` / `as` | для finished | Голы хозяев / гостей |

## events.csv

| Колонка | Обязательна | Что писать |
|---|---|---|
| `matchKey` | да | `key` матча из matches.csv |
| `type` | нет | `goal` (по умолчанию) · `yellow` · `red` · `sub`. Русские варианты тоже понимает: `гол`, `ЖК`, `КК`, `замена` |
| `minute` | да | Целое число. Для добавленного времени — `90` или `93` |
| `team` | да | `home` / `away` (или `хозяева` / `гости`) — **какая команда в этом матче**, а не «наши/чужие» |
| `player` | нет | Имя автора. Совпало с игроком в Sanity → ставится ссылка на профиль и гол попадёт в его статистику. Не совпало → сохранится текстом |
| `assist` | нет | Имя ассистента, логика та же |
| `ownGoal` | нет | `1` для автогола |

Строки, начинающиеся с `#`, игнорируются — в шаблонах так помечены примеры, их можно не удалять.

## Правка уже заведённых матчей

Скрипт сначала ищет матч в базе **по календарному дню и паре команд**. Если находит — патчит существующий документ, а не создаёт новый. Поэтому тем же CSV можно править то, что уже заведено руками: дозаполнить авторов голов, поправить номер тура, снять лишнее поле.

Правила при обновлении существующего:

- Записываются только непустые ячейки строки.
- `events`/`scorers` перезаписываются **только** если для этого `key` есть строки в `events.csv` — иначе правка тура не стёрла бы голы.
- Дата не трогается, если в CSV не указано время (в базе оно точнее).
- `finishedAt` не пересчитывается.
- Значение `-` в ячейке **удаляет** поле (например лишний `tour` у кубкового матча).

В отчёте прогона такие строки помечены «обновляю», новые — «создаю».

## Что делает скрипт

- **Идемпотентно.** У новых матчей `_id` = `match.import.<key>`. Перезапуск обновляет тот же документ. Дозаполнил авторов голов → перезапустил → добавились только они.
- **Считает `scorers[]` из `events[]`** по той же логике, что и кнопка «Завершить матч» в админке. Поэтому блок результатов на главной, последний матч в Hero и будущая страница матча видят одно и то же.
- **Проставляет `finishedAt`** (начало + 2 часа) — от него зависит 48-часовое окно показа результата на главной.
- **Сверяет счёт с числом голов** и предупреждает при расхождении, но записывает счёт из `matches.csv` (он достовернее, если протокол собран не полностью).
- **Связывает игроков по имени.** Не найденные выводятся списком в конце — это подсказка, где опечатка или кого не хватает в Studio.
- **Ничего не пишет без `--apply`.**

## Флаги

| Флаг | Зачем |
|---|---|
| `--apply` | Выполнить запись. Без него — только отчёт |
| `--create-teams` | Создавать отсутствующие команды автоматически (badge генерится из названия, потом поправить в Studio). Без флага такие матчи пропускаются с предупреждением |
| `--only=region-05` | Импортировать один матч |
| `--matches=data/cup.csv` | Другой файл матчей |
| `--events=data/cup-events.csv` | Другой файл событий |

## Типовые ситуации

**Соперника нет в базе.** Первый прогон сделать с `--create-teams`, потом зайти в Studio → Squad → Teams и поправить бейдж и логотип.

**Игрок не связался.** Проверить написание (скрипт нечувствителен к регистру и ё/е, но не к опечаткам). Если игрока нет в Sanity — завести и перезапустить импорт: имя заменится ссылкой на профиль, статистика пересчитается сама.

**Два игрока с одинаковым именем.** Скрипт не угадывает — пишет имя текстом и предупреждает. Связать вручную в Studio.

**Ошибся в счёте после импорта.** Поправить строку в CSV и перезапустить. Правки, сделанные в Studio руками, при этом затрутся — CSV является источником истины для импортированных матчей.

**Матч перенесли.** Поменять `date`, `key` оставить прежним.

## Ограничения

- Пенальти отдельным типом события схема пока не поддерживает — гол с пенальти пишется обычным голом.
- Составы на игру через CSV не заливаются (нужен третий файл и отдельный формат — сделаем, если понадобится).
- Турнирная таблица заполняется отдельным скриптом (ниже), а не этим.

## Турнирная таблица

Блок статистики на главной читает строку ФК Полоцк из `standingsTable`, а не суммирует матчи — иначе в очки попадают кубки, а недозаполненные туры занижают показатели.

```bash
pnpm --filter @fc-polotsk/studio seed:standings            # сухой прогон
pnpm --filter @fc-polotsk/studio seed:standings -- --apply # запись
```

Таблица задана массивом `ROWS` прямо в `scripts/seed-standings.ts` — команды по короткому коду, поля `пос · И · В · Н · П · забито · пропущено · очки`. Скрипт проверяет сходимость: сумма забитых должна равняться сумме пропущенных, `В+Н+П = И`, `В×3+Н = О`. При расхождении печатает предупреждение.

Флаг `isFinal` в документе переключает подпись под блоком с «Турнирная таблица» на «Итоговая таблица».
